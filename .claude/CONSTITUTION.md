# 拾贝 · 项目宪法

## 项目定位

**类型:** 架构原则
**日期:** 2026-08-01

拾贝是一个「社区内容 → LLM 提炼洞察」的命令行工具。抓取是手段，提炼是价值。所有代码围绕「来源可插拔、数据结构统一、LLM 接口标准」三条主线。

> **违反后果:** 脱离来源抽象写死 V2EX 细节、破坏统一数据结构、引入非 OpenAI 协议调用。

## Python 项目约定

**类型:** 编码规范
**日期:** 2026-08-01

遵守 `~/.claude/docs/python-project.md`：
- Python 3.10+，无第三方运行时依赖（crawler/analyzer 用标准库 urllib）。
- 用 uv 管理项目（可选，因零依赖，dev 依赖用 uv 管理 ruff/pytest/pyright）。
- 代码用 ruff format + ruff check，单行 ≤ 120 字符。
- 测试用 pytest；类型用 pyright；结构数据用 pydantic 约束（若引入）。

> **违反后果:** 引入无必要第三方依赖、未过 ruff/pyright 检查。

## API Key 安全

**类型:** 流程规则
**日期:** 2026-08-01

LLM API Key 不写入代码、不写入 config.json、不提交仓库，只通过环境变量 OPENAI_API_KEY 注入。

> **违反后果:** 泄漏凭据。

## 增量与幂等

**类型:** 架构原则
**日期:** 2026-08-01

所有抓取与分析必须可增量、可重跑：已存在的本地 JSON 不重复抓取；分析结果按 run_id 缓存；重跑不产生重复文件。

> **违反后果:** 重复请求 API 造成限流，或产生重复/不一致数据。
